# v0.2 Repository Audit

**Audit date:** 4 October 2026  
**Audited head:** `3106fbbbed8dd049f11b37772cd2319989f63a19`

## Summary

The v0.1 scaffold is a sound starting point. It already separates data, features, targets, models, splits, portfolio construction, backtesting and metrics; the CI workflow passes; and the code contains explicit tests for future-feature leakage, target timing, purging, portfolio constraints and transaction costs.

The repository should not yet be used for the v0.2 empirical baseline. Four items need to be fixed first.

## A1. Rolling data end moves the hold-out — blocking

`configs/baseline.json` currently has `"end": null`. Each fresh download therefore extends the sample and moves the final 252-session hold-out.

That defeats the purpose of a locked hold-out.

**Decision:** freeze the v0.2 market-data window at 3 October 2026 exclusive, giving 2 October 2026 as the final intended US session. Persist the hold-out date calendar once from that frozen snapshot.

## A2. Yahoo OHLC is currently unadjusted — blocking

`download_yahoo()` uses `auto_adjust=False` and the loader discards `Adj Close`. Split events and distributions can therefore enter price-derived features and return targets as artificial jumps.

This is material for a long ETF history.

**Decision:** the v0.2 data contract requires consistently adjusted OHLC prices. The Yahoo adapter should use adjusted OHLC. Provider-exported data must document the same convention.

## A3. Forecast horizon and portfolio horizon are inconsistent — blocking

The modelling target is a 5-session next-open-to-open return. The current backtest applies each daily score to a 1-session next-open-to-open return.

That changes the economic question and makes turnover/cost results difficult to interpret.

**Decision:** use five staggered 5-session sleeves. Each day's cohort enters at (t+1), remains active for five sessions, and the live portfolio is the equal-capital average of active cohorts.

## A4. Hold-out boundary is derived from the feature-complete frame — blocking

`prepare_research_frame()` constructs the hold-out after joining features and targets and dropping missing rows. A future feature with different missingness could therefore alter the hold-out calendar.

**Decision:** derive the hold-out once from the frozen session calendar and persist it independently of feature engineering.

## A5. Model and validation structure — satisfactory

The current expanding purged walk-forward design is appropriate for the initial study:

- 756-day minimum training history;
- 63-day test blocks;
- 63-day step;
- 6-day purge for a 5-session open-to-open target.

Ridge is an appropriate linear baseline and histogram gradient boosting is a reasonable nonlinear comparator. Broad hyperparameter search should not be added casually.

## A6. Inference — satisfactory with one extension

Daily Spearman rank IC with Newey-West/HAC inference at lag 4 is well aligned with the overlapping 5-session target.

v0.2 should add fold/year stability, IC information ratio and multiple-testing control when the candidate signal set expands.

## A7. Portfolio optimiser — defer from primary v0.2 result

The SLSQP alpha/risk/turnover optimiser is useful, but using it during first-pass signal discovery would mix alpha evidence with portfolio engineering.

**Decision:** keep the primary v0.2 economic diagnostic as the constrained rank portfolio. Move covariance-aware optimisation to the later optimisation phase.

## A8. Test coverage — good baseline; four tests to add

Current CI succeeds. Before the empirical run, add tests for:

1. fixed hold-out manifest independent of feature missingness;
2. adjusted-price data contract;
3. 5-session staggered-sleeve return alignment;
4. turnover and costs on the composite staggered portfolio.

## Gate for v0.2 empirical work

The empirical baseline can start after A1–A4 are implemented and the new tests pass. No hold-out outcomes are needed to make any of these corrections.
